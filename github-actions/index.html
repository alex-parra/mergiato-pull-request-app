GitHub Actions checks

Know why it's red, and re-run it from the PR.

A flaky job shouldn't cost you ten clicks through the Actions tab. Mergiato shows every check on the pull request, how long each job took and which one failed, and re-runs the failed jobs in one click.

Download for Mac

Free · no sign-up · Apple silicon and Intel Macs

Everything about a PR's checks, in one panel

  • Grouped by workflow, with nested job names like Web / test kept on one line. Each group shows its worst outcome.
  • Each job's time, colored by state and ticking while it runs. A workflow shows its total too.
  • Real totals. The panel's total counts only the time some job was running: jobs that overlap count once, and waiting in the queue isn't counted.
  • Live while jobs run. It refreshes every 10 seconds while any check is running, and every 30 seconds otherwise.

Re-run what failed, and only that

From You can
The panel's top row Re-run the failed jobs, or all jobs, across the PR's workflow runs
A workflow Re-run its failed jobs or all of them, or open the run on GitHub
A single job Re-run just that job, or open it on GitHub

A run that still has jobs in progress is skipped, because GitHub refuses to re-run it until it finishes.

Only the run that counts

A workflow can run several times on one commit: two PR events at once, or a re-run. Like GitHub, Mergiato counts only each job's newest run, so an old failure doesn't hang around after its re-run passes. The same rule applies to the check icon on every PR in your sidebar.

Cancelled runs are left out, and so is Graphite's mergeability_check, which stays "in progress" on stacked and draft PRs and would otherwise keep every stack yellow.

Questions

Does it work with checks other than GitHub Actions?

It shows every check GitHub reports for the PR's latest commit, from any app. Re-running uses GitHub Actions, so it applies to Actions jobs.

Will polling checks use up my rate limit?

Checks poll only for the PR you have open, every 10 seconds while jobs run and every 30 otherwise. Your inbox gets each PR's check state from the searches it already makes, at no extra cost.
