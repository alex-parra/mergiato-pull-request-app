Mergiato vs gh-dash

Both run on the GitHub CLI you're signed in to, so neither needs a token or an org app. gh-dash is a free, open-source dashboard in your terminal, driven by the keyboard and a config file. Mergiato is a desktop window built around the review itself: diffs, threads, checks, stacks and merges side by side.

gh-dash details checked on 18 October 2026, from gh-dash.dev and its GitHub repository.

The short answer

  • Pick gh-dash if you live in the terminal, want PRs and issues in sections you define yourself, and like to script your own commands.
  • Pick Mergiato if you want to read and comment on the diff itself, see each CI job, follow stacks, and merge through your repo's queue, in one window.

Where gh-dash is the better pick

  • You'd rather never leave the terminal, or you work over SSH.
  • You track issues next to PRs, in sections tuned to your own searches.
  • You want to bind your own commands, like opening lazygit on the PR's branch.
  • You want something open source you can change.

Where Mergiato is the better pick

  • You review big diffs and want to comment on the exact line, with every file in view. How it handles large PRs.
  • You fix red builds from the PR: each job, timed, re-run in one click.
  • Your team stacks PRs and merges through a queue: stacks in Mergiato.
  • You want it working the moment it opens, with nothing to configure.

Using both

They share the same gh sign-in, so there's nothing to set up twice. Keep gh-dash for a quick look from the terminal, and open the PR in Mergiato when it's time to read the diff and merge.
