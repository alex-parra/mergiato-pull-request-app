The problem

One review. Seven tabs. Zero altitude.

Reviewing a pull request shouldn't be a scavenger hunt. Today it means jumping between the PR, its files, the Actions logs, the preview dashboard, the stack, the chat thread that pinged you, and a terminal.

  • PR conversation
  • Files changed
  • Actions logs
  • Preview dashboard
  • Stack view
  • Notifications
  • Terminal
→ Mergiato: one window, every instrument.
Which PRs actually need me?

Your inbox splits what you're building from what's waiting on you, with a live count. No notification digging.

The diff is too big to load.

Hundreds of files, thousands of lines, no cap. Only what's near your view is drawn, so it never stalls.

Which check failed, and can I re-run it?

Each job's latest run, its state and its time. Re-run the failed ones, or one job, in a click.

Security won't approve another GitHub app.

There's nothing to approve. Mergiato uses the GitHub CLI you're already signed in to. Your access, your machine.

Zero rollout

Your team doesn't have to switch.

Mergiato is a better window onto GitHub, not a new place everyone has to move to. Your comments, reviews and merges land on GitHub exactly as if you'd made them there. Your teammates notice one thing: faster reviews from you.

Nothing to roll out

No org app, no seats, no admin. One person downloads it and starts reviewing.

Everything stays on GitHub

Comments, approvals, labels, merges: GitHub's own, visible to everyone as usual.

Works with your stack

Graphite stacks and merge queue, GitHub Actions, Vercel previews. Shown, not replaced.

Leave anytime

Drag it to the Trash. Nothing to cancel, nothing to revoke, nothing left behind on GitHub.

The console

Every control you need, within reach.

Not another diff viewer: the whole cockpit for shipping code. Find the PR, read the gauges, review, fix, deploy a preview and land the merge, without leaving the window.

Radar · Inbox

See what needs you

My PRs (in progress, merged) and Reviews (requested, reviewed by you), refreshed every 30 seconds. Close or merge one and it moves at once. Open any PR by link or number with ⌘F.

Gauges · Status

Read the PR at a glance

Review decision, approvers, checks, labels, assignees and its place in the stack, in a header that's there on every tab. Change reviewers, labels or the title right there.

Engines · Checks

Know why it's red

Each job's latest run (no stale duplicates), grouped and timed, live while running. Re-run what failed, or one job, without opening Actions.

Formation · Stacks

Fly stacked PRs

Graphite stacks shown as they are: what's above and below, with a jump to each. The merge queue's progress, and PRs it merged counted as merged.

Payload · Changes

Review any size of diff

File tree, unified or split, syntax colors, Viewed marks that reset when a file changes again, and one commit at a time when you want it.

Radio · Reviews

Talk where the code is

Comment on a line or a range, reply, resolve, react, edit your own. Approve or request changes from the header. Long threads fold, resolved ones tuck away.

Runway · Previews

Try it before you approve it

Each Vercel project's preview and state under the description. Deploy the branch's latest commit, or redeploy, from the PR.

Toolbox · Terminal

A shell in the PR's clone

Terminals docked under the PR, in your local clone, kept per PR and running while you look elsewhere. ⌘J to show or hide.

Autopilot · Updates

Always current

PRs refresh as they change, wherever the change came from. The app updates itself, signed, in the background. Six themes, light and dark.

Security

Your keys never leave the cockpit.

Most review tools ask you to install an app in your GitHub organization, grant it access to your repositories, and send your code through their servers. Mergiato doesn't.

It drives the tools you already use and trust, on your Mac: the GitHub CLI you're signed in to, git, and the Vercel CLI if you use it. Every request goes straight from your machine to GitHub, with your own access, exactly as if you typed the command. There's nothing for your security team to review, because there's no one new in the loop.

“It's the GitHub CLI, with a cockpit.” The one line to forward to your security team.

Pre-flight

Cleared for takeoff in a minute.

  1. Download the latest .dmg, open it and drag Mergiato to Applications.
  2. First open: macOS can't verify the developer yet, so allow it once in System Settings → Privacy & Security → Open Anyway. Updates don't ask again.
  3. Signed in to GitHub? If gh auth status says yes, you're done. If not, gh auth login once.

Needs macOS on Apple silicon and the GitHub CLI. Optional: the Vercel CLI, for previews. Mergiato keeps itself up to date.

FAQ

Questions from the tower

Is it free?

Yes, while in beta. Paid plans may come later, likely a one-time license; early users will hear first, and nothing you rely on will vanish overnight.

What can Mergiato see? Does my code go anywhere?

Exactly what your GitHub CLI can see, because that's what it uses. Requests go from your Mac straight to GitHub (and Vercel, if you use its CLI). There are no Mergiato servers, no account, no tokens kept by the app, and no analytics.

Do I need to install anything in my GitHub organization?

No. There's no GitHub App and no OAuth grant: if you can work on a repository from your terminal, you can review it in Mergiato.

Does my team need it too?

No. Everything you do lands on GitHub as usual, so it works for one person on a team of a hundred. Teammates who like what they see can download it themselves.

Does it work with Graphite?

Yes: it shows Graphite stacks and the merge queue, and links each PR to its Graphite page.

Intel Mac, Windows or Linux?

Apple silicon Macs for now. Intel Macs are next; Windows and Linux aren't planned yet.

Why does macOS warn on the first open?

Mergiato isn't signed with an Apple Developer ID yet, so macOS can't check it. Allow it once in System Settings → Privacy & Security. Some company-managed Macs block that entirely; signing is coming.
